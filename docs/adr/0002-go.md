# ADR 0002: Go for the control plane and the guest agent

- **Status:** Accepted
- **Date:** 2026-09-29

## Context

Roundhouse has two programs: a control plane on the host that drives
Firecracker, namespaces, and firewall rules, and an agent inside every guest
that runs commands. The agent must be a small static binary with no runtime
dependencies in the guest image. The control plane is mostly concurrent I/O:
HTTP, Unix sockets, process supervision, and streaming.

## Decision

Write both in Go. The control plane uses the standard library for HTTP and
process management and `golang.org/x/sys/unix` for Linux system calls. The
agent is built with `CGO_ENABLED=0` as a static Linux binary. Firecracker is
driven through its HTTP API directly rather than through an SDK, so every call
is visible in the code.

## Consequences

- One toolchain, one set of standards (coding-standards.md), and one module for
  host and guest, with shared wire types in `internal/agentproto`.
- Static agent binaries need no libc in the guest.
- E2B's production orchestrator and guest daemon are also Go, so the approach
  is proven at scale.
- Go's garbage collector is irrelevant to the start path, which is dominated by
  process start and memory mapping, but allocations on the exec relay are
  measured like any hot path.
